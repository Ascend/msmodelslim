# Qwen3-32B W8A8 Accuracy Tuning Case

## 1. Case Background

This case tunes the issue of garbled conversational output after W8A8 quantization of the Qwen3-32B model. The initial solution used fully static quantization (per-channel/per-tensor) together with the Smooth Quant outlier suppression algorithm, but the quantized model produced garbled conversations. After systematic tuning, the accuracy of the quantized model on the AIME25 dataset increased from unusable to 70.00%. In addition, the effects of two alternative optimization measures, calibration dataset adjustment and quantization rollback, were verified on the GPQA dataset.

This case actually covers the 5 steps of the *[Quantization Accuracy Tuning Guide](../user_guide/process_quantization_precision_tuning.md)*: confirm that the accuracy issue is credible → adjust the outlier suppression algorithm → adjust the quantization strategy → adjust the calibration dataset → quantization rollback.

**Related process**: *[Quantization Accuracy Tuning Guide](../user_guide/process_quantization_precision_tuning.md)*

## 4. Procedure

### Command Conventions

**Quantization command**: All quantization experiments in this case are executed with the following command. Fill in the path parameters according to the actual environment:

```bash
# Fill in the following paths according to the actual environment
MODEL_PATH=/path/to/qwen3-32b      # Floating-point model weight directory
SAVE_PATH=/path/to/save            # Quantization output directory
CONFIG_PATH=/path/to/config.yaml   # Quantization configuration YAML

msmodelslim quant \
    --model_type Qwen3-32B \
    --model_path ${MODEL_PATH} \
    --save_path ${SAVE_PATH} \
    --device npu \
    --config ${CONFIG_PATH} \
    --trust_remote_code true
```

**Evaluation command**: Accuracy evaluation is performed with the AISBench tool. For usage, see [AISBench Quick Start](https://github.com/AISBench/benchmark/blob/master/docs/source_en/get_started/quick_start.md). This case uses the dataset configurations `aime2025_gen_0_shot_chat_prompt` (AIME25) and `gpqa_gen_0_shot_cot_chat_prompt` (GPQA). For dataset descriptions, see [AIME25](https://github.com/AISBench/benchmark/blob/master/ais_bench/benchmark/configs/datasets/aime2025/README.md) and [GPQA](https://github.com/AISBench/benchmark/blob/master/ais_bench/benchmark/configs/datasets/gpqa/README.md).

### Step 1: Confirming That the Accuracy Issue Is Real

**Objective**: Rule out environmental interference and confirm that the accuracy issue really exists.

**Inputs**: The floating-point model, the quantized weights of the initial configuration, the AIME25 evaluation dataset, the target inference engine (such as vLLM Ascend), and the AISBench model configuration that points to its service.

**Operations**:

1. Deploy the floating-point model to the target inference engine, and use AISBench to complete the AIME25 baseline evaluation as per the command conventions (use a working directory separate from subsequent experiments) to confirm that the original accuracy can be reproduced.
2. Deploy the initial quantized model (the W8A8 + Smooth Quant output) and run the same AIME25 evaluation, then check the output: confirm that the garbled text is not caused by non-quantization issues such as context truncation or timeouts (spot-check the generated content in the inference logs if necessary).
3. Considering the accuracy fluctuation range of the AIME25 dataset, determine that the current accuracy loss is abnormal and confirm that it is introduced by quantization.

**Output**: The AIME25 baseline evaluation report of the floating-point model; confirmation that the accuracy issue is introduced by quantization, together with samples of the garbled output from the quantized model.

**Record**: The AIME25 baseline accuracy of the floating-point model and the path to the garbled output log of the quantized model.

**Next step**: Step 1 confirms that the floating-point baseline is normal and that the garbled text is introduced by quantization (the accuracy of the initial Smooth Quant configuration is far below the target). Proceed to Step 2 to adjust the outlier suppression algorithm.

### Step 2: Adjusting the Outlier Suppression Algorithm (Key Step)

**Objective**: Eliminate garbled conversations and improve accuracy by switching the outlier suppression algorithm.

**Inputs**: Outlier suppression algorithm configurations, the floating-point model, and the AIME25 evaluation dataset.

**Operations**:

1. **Tune one by one in priority order**: Follow the tuning order of Iterative Smooth first, then asymmetric → symmetric → adjusting alpha → other algorithms, and execute the following loop each time: generate configuration → quantize → deploy and evaluate. At each step, decide based on the evaluation result whether to continue to the next step (all with the same `linear_quant` static quantization and `save` format). The key points of each algorithm configuration are as follows (for complete parameters, see the algorithm documentation):

   a. **Iterative Smooth (asymmetric/alpha:0.5)**: Try the asymmetric scheme first. The asymmetric scheme supports only the `norm-linear` subgraph. For details, see *[Iterative Smooth Algorithm](../knowledge_base/quantization_algorithms/iterative_smooth/usage_iterative_smooth.md)*.

   b. **Iterative Smooth (symmetric/alpha:0.5)**: Switch to the symmetric scheme and use the default alpha value of 0.5. For details, see *[Iterative Smooth Algorithm](../knowledge_base/quantization_algorithms/iterative_smooth/usage_iterative_smooth.md)*. — If the accuracy does not meet the target after evaluation, adjust alpha.

   c. **Iterative Smooth (symmetric/alpha:0.9)**: Keep the symmetric scheme and increase alpha to 0.9. For details, see *[Iterative Smooth Algorithm](../knowledge_base/quantization_algorithms/iterative_smooth/usage_iterative_smooth.md)*. — If the accuracy still does not meet the target after evaluation, switch to another outlier suppression algorithm.

   d. **Flex Smooth Quant (alternative)**: alpha/beta are automatically searched by default. For details, see *[Flex Smooth Quant Algorithm](../knowledge_base/quantization_algorithms/flex_smooth_quant/usage_flex_smooth_quant.md)*. — Use only when none of the Iterative Smooth schemes meets the target.

   For an algorithm comparison, see [Outlier Suppression Algorithms](../knowledge_base/quantization_algorithms/README.md#1-outlier-suppression-algorithms).

2. **Deploy and evaluate**: Deploy each group of quantized output to the target inference engine, run the evaluation command (AIME25 dataset), and record the accuracy and quantization time.
3. **Summarize and compare**: Summarize the accuracy and quantization time of each algorithm and select the overall best scheme.

| Tuning Order | Outlier Suppression Algorithm | AIME25 Accuracy (%) | Quantization Time (s) | Remarks |
|---------|---------------|-----------------|--------------|------|
| Initial | Smooth Quant | 0 | 326 | Initial configuration; garbled output |
| 1st | Iterative Smooth (asymmetric/alpha:0.5) | 0 | 305 | Garbled output; switch to symmetric |
| 2nd | Iterative Smooth (symmetric/alpha:0.5) | 3.33 | 324 | Repeated token output; accuracy below the target; adjust alpha |
| 3rd | Iterative Smooth (symmetric/alpha:0.9) | 63.33 | 319 | The accuracy is normal but does not reach the preset accuracy requirement (70.00%); switch to the Flex Smooth Quant algorithm |
| 4th | Flex Smooth Quant | 13.33 | 1380 | Repeated token output, and the time required is noticeably longer |

**Output**: The quantized weights and the corresponding AIME25 evaluation report; the outlier suppression algorithm is determined to be Iterative Smooth (symmetric/alpha:0.9).

**Record**: The measured accuracy and quantization time data of the 5 configurations in the table above. Comparative analysis: symmetric/alpha:0.5 (3.33%), asymmetric/alpha:0.5 (0%), and Flex Smooth Quant (13.33%) all show severe degradation with repeated tokens/garbled text under per-tensor static activation quantization; only symmetric/alpha:0.9 has normal accuracy (63.33%), but it still does not reach the preset accuracy requirement (70.00%), so it is necessary to proceed to Step 3 to further adjust the quantization strategy. The quantization time is 319 seconds, which saves 76.9% compared with Flex Smooth Quant.

**Next step**: The best configuration of Step 2 (Iterative Smooth symmetric/alpha:0.9) achieves an AIME25 accuracy of 63.33%, which does not reach the preset accuracy requirement (70.00%). Proceed to Step 3 to adjust the quantization strategy with the outlier suppression algorithm fixed.

### Step 3: Adjusting the Quantization Strategy

**Objective**: After the outlier suppression algorithm is determined, further improve the accuracy by switching the weight quantization method and the activation quantization granularity.

**Inputs**: The base configuration determined in Step 2 (Iterative Smooth (symmetric/alpha:0.9)), quantization strategy configurations (the `per_tensor`/`per_token` activation quantization granularities under the `minmax` method), and the AIME25 evaluation dataset.

**Operations**:

1. **Tune one by one in priority order**: You can first try the two methods `per_tensor` (static quantization) and `per_token` (dynamic quantization). If neither `per_tensor` nor `per_token` meets the target, you can refer to *[Quantization Accuracy Tuning Guide - Quantization Algorithm Selection](../user_guide/process_quantization_precision_tuning.md#step-3-choosing-the-quantization-algorithm)* and try other quantization strategies, such as switching the weight quantization method (`ssz`/`gptq`/`autoround`) or the activation quantization method (`histogram`), or using the `pd_mix` mixed granularity.

   a. **per_tensor (static quantization)**: In the `linear_quant` processor of the quantization configuration YAML, set `qconfig.act.scope` to `per_tensor` and run the quantization command. For the `linear_quant` processor parameters, see *[Linear Quant Algorithm](../knowledge_base/quantization_algorithms/linear_quant/usage_linear_quant.md)*; for the quantization method parameters, see [MinMax](../knowledge_base/quantization_algorithms/minmax/usage_minmax.md). — If the accuracy does not meet the target after evaluation, switch to per_token.

   b. **per_token (dynamic quantization)**: Change `qconfig.act.scope` to `per_token` and run the quantization command. — If the accuracy still does not meet the target after evaluation, refer to the guide link above and try other quantization strategies.

2. **Deploy and evaluate**: Deploy each group of quantized output and run the evaluation command, then record the quantization time and the AIME25 dataset accuracy.
3. **Summarize and compare**: Compare the accuracy and quantization time and select the overall best configuration.

| Weight Quantization Method| Activation Quantization Granularity| AIME25 Accuracy (%)| Quantization Time (s)| Remarks|
|-------------|-------------|----------------|-------------|------|
| minmax | per-tensor (static quantization) | 63.33 | 319 | Base configuration (based on the Step 2 result) |
| minmax | per-token (dynamic quantization) | 70.00 | 289 | After per-token is used for activations, the accuracy improves by 6.67 percentage points and meets the target |

**Output**: 2 groups of quantized weights and the corresponding AIME25 evaluation reports; the quantization strategy is determined to be **minmax + per-token (dynamic quantization)**.

**Record**: The measured accuracy and quantization time data of the 2 configurations in the table above. Comparative analysis: per-token dynamic quantization (70.00%) outperforms per-tensor static quantization (63.33%), with an accuracy improvement of 6.67 percentage points, meeting the preset accuracy requirement (70.00%), and the quantization time is shorter (289 s vs. 319 s).

**Next step**: Step 3 reaches the preset accuracy requirement (70.00%). To demonstrate the complete tuning process and verify the effects of calibration dataset adjustment and quantization rollback, proceed to Step 4.

### Step 4: Adjusting the Calibration Dataset

**Objective**: Verify the improvement in quantization accuracy through calibration dataset optimization (adding badcase samples). This step uses the GPQA dataset (which has more questions and can show the accuracy difference between configurations more clearly).

**Inputs**: The quantization configuration that met the accuracy requirement in Step 3 (this section uses Iterative Smooth + static quantization as the base configuration for verification on the GPQA dataset), the GPQA evaluation result of this base configuration (including badcase samples), the calibration dataset file, and the GPQA evaluation dataset.

**Operations**:

1. **Add badcase samples**: For calibration dataset optimization strategies, see [Quantization Accuracy Tuning Guide - Calibration Dataset Adjustment](../user_guide/process_quantization_precision_tuning.md#step-4-adjusting-the-calibration-set). This case applies the "add badcase" strategy. The default calibration dataset `mix_calib.jsonl` (48 entries) is used, and 5 badcases are added to make 53 entries.

2. **Obtain badcase samples**: From the AISBench evaluation result file, filter the samples for which "the model output (the `prediction` field) is inconsistent with the reference answer (the `gold` field)" and extract a small number of badcases. For example, one badcase sample is:

   ```text
   What is the correct answer to this question: Two quantum states with energies E1 and E2 have a lifetime of 10^-9 sec and 10^-8 sec, respectively. We want to clearly distinguish these two energy levels. Which one of the following options could be their energy difference so that they can be clearly resolved?

   Choices:
   (A)10^-11 eV
   (B)10^-8 eV
   (C)10^-9 eV
   (D)10^-4 eV
   Format your response as follows: "The correct answer is (insert answer here)"
   ```

3. **Format conversion**:

   - **JSONL format**: Referring to the calibration dataset file [`msmodelslim/lab_calib/mix_calib.jsonl`](../../../lab_calib/mix_calib.jsonl), place the text in the `"inputs_pretokenized"` field, as follows:

     ```json
     {"inputs_pretokenized":"What is the correct answer to this question: Two quantum states with energies E1 and E2 have a lifetime of 10^-9 sec and 10^-8 sec, respectively. We want to clearly distinguish these two energy levels. Which one of the following options could be their energy difference so that they can be clearly resolved?\n\nChoices:\n(A)10^-11 eV\n(B)10^-8 eV\n\n(C)10^-9 eV\n(D)10^-4 eV\nFormat your response as follows: \"The correct answer is (insert answer here)\""}
     ```

   - **JSON format**: Referring to [`msmodelslim/lab_calib/qwen3_cot_w4a4.json`](../../../lab_calib/qwen3_cot_w4a4.json), simply add the text to the string list.

   Merge the badcase samples with the original calibration dataset samples to generate a new calibration dataset file (48→53 entries in this case).

4. **Re-quantize**: In the quantization configuration YAML, specify the calibration dataset file with badcases added through the `dataset` field under `spec`. For the remaining processors and the `save` configuration, refer to the YAML example in Step 5 (only the `iter_smooth` and `linear_quant` parts, without the `exclude` rollback layers), and use the quantization command from the command conventions to regenerate the quantized weights.

5. **Evaluation verification**: Deploy each group of quantized output and run the evaluation command, then record the GPQA dataset accuracy.

**Output**: The badcase calibration dataset and the regenerated quantized weights. The GPQA accuracy increases from the baseline 48.98% to 57.07% (an improvement of 8.09 percentage points).

| Quantization Strategy| GPQA Accuracy (%)| Remarks|
|-------------|---------------|------|
| Iterative Smooth + static quantization | 48.98 | Base configuration |
| Iterative Smooth + static quantization + badcase calibration dataset adjustment | 57.07 | The accuracy improves by 8.09 percentage points compared with the base configuration, indicating that badcase samples help the quantized model learn difficult samples and improve quantization accuracy |

**Record**: The measured GPQA accuracy data of the 2 configurations in the table above.

**Next step**: To demonstrate the complete tuning process and verify the effect of quantization rollback, proceed to Step 5.

### Step 5: Quantization Rollback (Alternative Option)

**Objective**: Verify the improvement in quantization accuracy achieved by rolling back quantization-sensitive layers to floating-point precision.

**Inputs**: The quantization configuration of Step 2 (Iterative Smooth + static quantization), the GPQA evaluation dataset, and the default calibration dataset.

**Operations**:

1. **Sensitive layer analysis**: Use the msModelSlim sensitive layer analysis tool to identify quantization-sensitive layers. For detailed usage, see the *[Quantization Sensitive Layer Analysis Usage Guide](../user_guide/usage_sensitive_linear_analysis.md)*.

   ```bash
   # Fill in the following paths according to the actual environment
   MODEL_PATH=/path/to/qwen3-32b      # Floating-point model weight directory

   msmodelslim analyze linear \
       --model_type Qwen3-32B \
       --model_path ${MODEL_PATH} \
       --device npu \
       --top_k 18 \
       --metrics kurtosis
   ```

   Sorted by quantization sensitivity score from high to low, the top sensitive layers are as follows:

   ```text
   layers.3.mlp.down_proj
   layers.63.mlp.down_proj
   layers.2.mlp.down_proj
   layers.1.mlp.down_proj
   layers.4.mlp.down_proj
   layers.6.mlp.down_proj
   layers.7.mlp.down_proj
   layers.5.mlp.down_proj
   layers.0.mlp.down_proj
   layers.31.mlp.down_proj
   layers.62.mlp.down_proj
   layers.5.mlp.gate_proj
   layers.5.mlp.up_proj
   layers.32.mlp.down_proj
   layers.8.mlp.gate_proj
   layers.8.mlp.up_proj
   layers.6.mlp.gate_proj
   layers.6.mlp.up_proj
   ```

   The analysis result shows that the `mlp.down_proj` layers rank high in sensitivity and are the layer type that is more difficult to quantize, so they should be rolled back first.

2. **Modify the quantization configuration**: In the quantization configuration YAML, roll back the 9 most sensitive layers (all `mlp.down_proj` layers) through the `exclude` field:

   ```yaml
   apiversion: modelslim_v1
   spec:
     process:
       - type: "iter_smooth"          # Parameters are the same as Step 2 (symmetric/alpha:0.9)
         ...
       - type: "linear_quant"
         qconfig:
           act:
             scope: "per_tensor"
             dtype: "int8"
             symmetric: false
             method: "minmax"
           weight:
             scope: "per_channel"
             dtype: "int8"
             symmetric: true
             method: "minmax"
         include:
           - "*"
         exclude:
           - 'model.layers.3.mlp.down_proj'
           - 'model.layers.63.mlp.down_proj'
           - 'model.layers.2.mlp.down_proj'
           - 'model.layers.1.mlp.down_proj'
           - 'model.layers.4.mlp.down_proj'
           - 'model.layers.6.mlp.down_proj'
           - 'model.layers.7.mlp.down_proj'
           - 'model.layers.5.mlp.down_proj'
           - 'model.layers.0.mlp.down_proj'
     save:
       - type: "ascendv1_saver"
         part_file_size: 4
   ```

3. **Regenerate the quantized weights**: Run the quantization command with the modified configuration to generate a quantized model that includes the rollback layers.

4. **Evaluation verification**: Deploy the quantized output and run the evaluation command, then record the GPQA dataset accuracy.

**Output**: A quantized model with 9 rollback layers. The GPQA accuracy increases from the baseline 48.98% to 49.49% (an improvement of 0.51 percentage points).

| Quantization Strategy| GPQA Accuracy (%)| Remarks|
|-------------|---------------|------|
| Iterative Smooth + static quantization | 48.98 | Base configuration |
| Iterative Smooth + static quantization + rolling back the first 9 layers | 49.49 | The accuracy improves by 0.51 percentage points compared with the base configuration, indicating that rolling back quantization-sensitive layers can effectively improve quantization accuracy, but it brings a certain performance overhead and an increase in model size |

**Record**: The measured GPQA accuracy data of the 2 configurations in the table above.

**Next step**: The tuning is complete.

## 5. Results and Lessons Learned

### 5.1 Summary of Key Results

| Step | Key Operation | Metric | Change | Remarks |
|------|---------|------|------|------|
| Initial state | Smooth Quant + minmax static quantization | AIME25 accuracy: 0% | — | Initial configuration; the quantized model is unusable |
| Step 2 | Switch to Iterative Smooth (symmetric/alpha:0.9) | AIME25 accuracy: 63.33% | Garbled text → 63.33% | The garbled text problem is resolved and the model becomes usable |
| Step 3 | Switch activation quantization to per-token (dynamic quantization) | AIME25 accuracy: 70.00% | +6.67 percentage points | Reaches the preset accuracy requirement (70.00%) |
| Step 4 | Add badcase samples to the calibration dataset | GPQA accuracy: 57.07% | +8.09 percentage points | Relative to the GPQA baseline (48.98%); alternative verification |
| Step 5 | Roll back the first 9 sensitive layers (mlp.down_proj) | GPQA accuracy: 49.49% | +0.51 percentage points | Relative to the GPQA baseline (48.98%); alternative verification |

**Note**: Step 3 already meets the preset accuracy requirement after reaching 70.00% accuracy; Steps 4 and 5 verify the effects of two alternative measures, calibration dataset adjustment and quantization rollback, on the GPQA dataset, demonstrating the complete tuning path.

**Final configuration**:

- **Outlier suppression algorithm**: Iterative Smooth (symmetric/alpha:0.9).
- **Weight quantization**: `minmax`, `per_channel`, int8 data type, symmetric quantization
- **Activation quantization**: `minmax` method, `per_token` granularity (dynamic quantization), `int8` data type.

### 5.2 Lessons Learned

1. **The outlier suppression algorithm is key**: Switching from Smooth Quant to Iterative Smooth (symmetric/alpha:0.9) raises the AIME25 accuracy from garbled output to 63.33%, making the quantized model usable. Applicable boundary: Iterative Smooth is preferred, and the asymmetric scheme is usually better than the symmetric scheme, but it requires adaptation support from the inference engine, so the inference engine's support for the outlier suppression algorithm must be confirmed before quantization.

2. **Prioritize adjusting the activation quantization granularity**: Switching from per-tensor (static quantization) to per-token (dynamic quantization) raises the AIME25 accuracy from 63.33% to 70.00% (+6.67 percentage points) and shortens the quantization time (289 s vs. 319 s), meeting the target without changing the weight quantization method. Applicable boundary: per-token dynamic quantization is more computationally complex and may cause a certain inference performance loss; when performance is the priority, the `pd_mix` mixed strategy can be used instead; if the target is still not met after adjusting the activation quantization granularity, weight quantization methods such as ssz can be tried.

3. **Calibration dataset quality affects accuracy**: On the GPQA dataset, adding badcase samples to the calibration dataset raises the accuracy from 48.98% to 57.07% (+8.09 percentage points). Applicable boundary: a data volume of 10–50 entries is recommended, and the data must match the task and language (use English data for English models); the badcases must come from the same evaluation dataset to reliably reproduce the benefit.

4. **Quantization rollback is a last resort**: On the GPQA dataset, rolling back 9 quantization-sensitive layers raises the accuracy from 48.98% to 49.49% (+0.51 percentage points). Applicable boundary: rollback brings a performance overhead and an increase in model size, so it should be used when other measures cannot meet the requirements; `mlp.down_proj` is usually a sensitive layer and can be rolled back first.
