# Quantile 参数配置流程指南

## 1. 适用范围

本指南面向需要使用 [Quantile 敏感层分析算法](./term_quantile.md) 的用户。Quantile 作为 `msmodelslim analyze linear` 的 metrics 指标，用于线性层粒度的敏感度排序，对离群点相对稳健。

适用场景：

- 需要在线性层粒度上筛选“极值相对主体区间异常”的敏感层，作为回退、提位宽或重点保护的候选；
- 需要一个对极值稳健、不依赖量化损失近似计算的快速敏感度代理指标。

模型是否在官方预验证列表中请参考[《大模型支持矩阵》](../../model/README.md)；如需快速了解 CLI 基础用法可参阅[《一键量化完整指南》](../../../user_guide/usage_one_click_quantization.md)。

## 3. 流程总览

Quantile 的整体使用流程如下：

```mermaid
flowchart LR
    A[确定线性层范围] --> B[固定<br/>metrics=quantile]
    B --> C[统计<br/>分位数/IQR]
    C --> D[按稳健 score<br/>排序]
    D --> E[选择回退候选]
```

各阶段的关键细节如下：

- **前置条件：模型适配**：分析前需先完成模型适配，适配器实现 `PipelineInterface`（基础流水线接口）等接口，详见[《LLM 模型接入量化流程指南》](../../ptq/llm/integration_guide_large_language_model_quantization.md)。模型适配必须先完成，才能执行分析流程。
- **确定线性层范围**：通过 `--patterns` 圈定待统计的线性模块名模式，第一次建议覆盖与实际量化计划一致的范围。
- **固定 metrics=quantile**：`--metrics quantile` 选定本指南对应的分析指标，决定 score 的定义和排序含义。
- **统计分位数/IQR**：在线性/卷积类模块激活上计算绝对最大值与四分位距（IQR）的比值构造 score；score 越高通常表示“整体主体分布较窄，但少量极值把动态范围拉得很大”。
- **按稳健 score 排序**：将各线性层的 score 排序，得到敏感度候选列表；排序结果受校准数据、候选范围和指标定义共同影响。
- **选择回退候选**：将 Top-K 高分对象作为“回退/提位宽候选池”，最终是否回退仍应结合实际量化精度或任务指标验证。

## 4. 操作步骤

### 步骤 1：确认目标与约束

**操作**：固定待分析模型、正式量化基线、校准数据和分析范围。先确认本次分析是为了筛选线性层、Decoder 层、Attention 结构或其他候选对象，并让分析范围与后续实际量化范围一致。如果模型、校准数据、量化基线或候选范围同时变化，分数排序将难以归因，因此这些条件应先固定，再调整指标或候选数量。

**输出**：一份固定的分析上下文：模型版本、量化基线、校准数据、分析范围以及要解决的回退/混合精度问题。

### 步骤 2：建立推荐配置

**操作**：

- 分析范围：`linear`；
- `--metrics`：`quantile`；
- `--top_k`：先用 `15`；
- `--patterns`：先用 `"*"`，建立全量线性层基线；

**输出**：一组可复现的敏感性分析基线参数，用于生成第一版候选排序。

### 步骤 3：选择并调整参数

**操作**：

| 配置项 | 含义（原理） | 推荐配置 | 什么时候调整 |
| --- | --- | --- | --- |
| 分析范围 `linear` | 在线性/卷积类模块激活上使用绝对最大值与四分位距（IQR）的比值构造 score。实现对排序激活做抽样，score 越高通常表示“整体主体分布较窄，但少量极值把动态范围拉得很大”。 | 固定 `linear`。 | 固定 linear；适合识别长尾/离群相对主体分布特别突出的层。 |
| `--metrics` | 选择本指南对应的分析指标 `quantile`；指标决定 score 的定义和排序含义。 | 固定 `quantile`。 | 固定 `quantile`。其 score 是稳健分布代理，不等于真实量化 MSE；尤其不同层 IQR 很小时分数会被放大，应结合其他指标验证。 |
| `--patterns` | 限制统计的线性模块名称模式。 | 第一次 `["*"]`，正式分析对齐要量化的模块族。 | 第一次分析应覆盖与实际量化计划一致的候选范围；只有确认某类模块不会量化时才收窄。范围变化会改变候选集合，因此不同范围下的排名不要直接当成同一次实验比较。 |
| `--calibration_dataset` | 用于前向收集激活或浮点/量化输出的校准数据，**JSON/JSONL 格式**（LLM 文本样本文件，如 `mix_calib.jsonl`；VLM 为多模态目录）。数据分布直接决定统计量、MSE 或 Head 分数，因此它是影响分析有效性的核心输入，而不是普通文件路径。 | 优先使用**与后续正式量化相同或同分布**的校准集，推荐 50 条样本；快速验证才使用内置示例。 | 如果排序在不同数据上明显变化，先判断校准集是否覆盖真实长度、主题和输入形态，再考虑扩大 `top_k`。正式回退决策应尽量在代表性数据上完成。 |
| `--top_k` | 控制最终展示/导出的高分候选数量，默认 `15`。它不改变底层 score 计算，也不会让算法重新分析更多数据。 | 从 `15` 开始。 | 候选只是后续验证集合：需要更多回退候选时增大，需要快速人工审查时减小。不要把 `top_k` 当作敏感度阈值；不同模型、不同指标的绝对 score 尺度并不统一。 |

#### 参数组合与结果解释

- **先固定校准集和量化基线，再比较排序**。如果同时换了数据、量化配置和分析范围，score 的变化无法归因。
- **高分表示“按 `quantile` 定义更值得关注”，不等价于一定要回退**。应把 Top-K 当作候选集，再用实际量化精度或模型任务指标验证。
- **`top_k` 只改变输出规模**。真正影响“谁排在前面”的通常是校准数据、候选范围以及本指标自身的统计定义。

Quantile 比纯 max 更关注“极值相对主体区间有多异常”。它适合筛选需要平滑/更细粒度的候选层，但是否回退仍应由实际量化评测决定。

**输出**：一份参数含义和调整方向明确的分析配置；修改项能够与排序变化建立对应关系。

### 步骤 4：解释结果并收敛候选方案

**操作**：

- Score 较高的对象优先进入“回退/提位宽候选池”，但最终是否回退仍应结合端到端精度验证。
- `top_k` 只是候选展示数量，不是精度阈值；不要把第15名等位置机械当成回退边界。
- 分析范围（`patterns`/`quant_modules`）应尽量与实际量化范围一致，否则得到的排序无法准确指导最终 YAML。

**输出**：一份经过实际量化或任务指标验证的敏感对象候选，以及对应的局部回退、提位宽或保护建议。
