# msModelSlim 资料规范

## 1. 概述

### 1.1 编写目的

本规范定义 msModelSlim 资料的编写、评审与维护要求，为资料工作提供统一依据，主要目的如下：

- **保证质量**：明确各类文档的编写要求与校验机制，确保资料内容准确、结构完整、表达清晰，满足目标读者的使用需求。
- **指导编写**：提供文档分类方法、模板与写作要求，使资料编写人员有章可循，降低编写与学习成本。
- **支撑评审**：提供客观、可执行的校验依据，使资料评审结论有据可查，减少主观判断与沟通成本。
- **服务读者**：从用户业务出发组织资料，保证资料易于检索、导航与理解，使读者能够快速找到所需信息。
- **支持演进**：为资料体系的持续维护、扩展与迭代提供稳定的规范基础。

### 1.2 适用范围

本规范适用于 `docs/` 目录下的资料，覆盖资料从规划、编写、评审到维护的全过程；其中中文资料为强制执行范围，其他语言版本为参考范围。

- **强制范围**：以 `docs/zh/` 中文资料树为强制执行范围，是资料校验与评审的直接依据。
- **参考范围**：英文树（`docs/en/`）及其他语言版本的资料仅作参考执行，不纳入强制校验范围。
- **覆盖全部文档类型**：既包括模板体系内文档（共5类，见[第2.2节](#22-文档类型)），也包括安装指南、快速入门、FAQ、版本说明、法律声明等模板体系外文档。
- **不适用范围**：代码注释、代码提交信息等由代码承载的内容，不属于本规范范围，其要求见《[编码规范](../coding_standards.md)》。

### 1.3 读者对象

本规范面向参与 msModelSlim 资料工作的各类角色，不同角色的关注重点如下：

| 读者角色 | 主要用途 |
| --- | --- |
| 资料编写人员 | 依据文档分类方法选择文档类型，套用对应模板编写内容，并按校验清单自查后提交。 |
| 资料评审人员 | 依据校验清单判定文档是否通过，给出有据可查的评审结论与修改意见。 |
| 资料维护人员 | 依据文档生命周期与导航关系，随功能演进同步新增、更新、合并或下线资料，保持资料体系一致。 |
| SIG 评审成员 | 依据第4.2节与规范维护章节，评审文档豁免申请与规范变更，把控规范本身的演进方向。 |

> 普通用户查阅 msModelSlim 资料时无需阅读本规范，直接阅读面向用户的文档内容即可。

## 2. 文档体系

### 2.1 文档分层

`docs/zh` 资料分为六层，各层定位如下：

| 层级 | 目录 | 定位 |
| --- | --- | --- |
| 入门层 | `install_guide/`、`quick_start/` | 入门指引：安装与环境准备、快速上手 |
| 使用层 | `user_guide/`、`best_practices/` | 操作知识：业务流程指南、工具使用指南与实践案例 |
| 知识层 | `knowledge_base/` | 领域知识：量化算法、调优策略、量化格式等概念及其应用 |
| 接口层 | `api_reference/` | 接口参考：命令行、配置等 API 文档 |
| 支撑层 | `support/`（FAQ）、`release_notes/`、`legal/` | 辅助信息：常见问题解答、版本说明与法律声明 |
| 治理层 | `contributing/` | 治理规范：贡献指南、设计文档、开发规范与资料规范等 |

### 2.2 文档类型

**模板体系内文档（5类）**，结构遵循对应模板，提交前按对应校验清单检查：

| 类型 | 所属层级 | 定位 | 模板 | 校验清单 |
| --- | --- | --- | --- | --- |
| 术语词条 | 知识层 | 陈述性知识：说明术语的定义、原理、性质与关联关系 | 《[术语词条模板](./01_term_glossary_template.md)》 | 《[术语词条校验清单](./01_term_glossary_checklist.md)》 |
| 流程指南 | 使用层 | 过程性知识：说明适用范围、输入与交付件、操作步骤 | 《[流程指南模板](./02_process_guide_template.md)》 | 《[流程指南校验清单](./02_process_guide_checklist.md)》 |
| 案例参考 | 使用层 | 实践案例：记录背景、环境、步骤、结果与经验 | 《[案例参考模板](./03_general_case_template.md)》 | 《[案例参考校验清单](./03_general_case_checklist.md)》 |
| 配置文档 | 接口层 | 接口参考：说明配置字段、约束与取值 | 《[配置文档模板](./04_config_document_template.md)》 | 《[配置文档校验清单](./04_config_document_checklist.md)》 |
| CLI 文档 | 接口层 | 接口契约：说明命令名、参数与调用约定 | 《[命令行 API 文档模板](./05_cli_api_contract_template.md)》 | 《[命令行 API 文档校验清单](./05_cli_api_contract_checklist.md)》 |

> **受众与详略**：使用指南（流程指南）面向入门用户，以详细步骤引导其选择参数、填写配置并执行；API 文档与配置文档面向高阶用户，供其快速检索查阅，只需明确命令名、参数与取值等参考信息，不展开步骤讲解。

**模板体系外文档**：安装指南、快速入门、FAQ、版本说明、法律声明以及各目录下的说明文件等，不套用模板，分布于多个层级（例如入门层的安装指南与快速入门、支撑层的 FAQ 与版本说明），遵循《[公共校验清单](00_common_checklist.md)》中的通用编写要求，并至少满足其中标记为 ERROR 的条目。

### 2.3 文档类型选择

根据待编写内容的性质与用途确定文档类型：

| 内容特征 | 文档类型 |
| --- | --- |
| 概念或算法的定义、原理与性质说明 | 术语词条 |
| 任务的操作步骤与执行流程说明 | 流程指南（含使用指南） |
| 实践活动的背景、过程、结果与经验记录 | 案例参考 |
| 配置类接口的字段、约束与取值说明 | 配置文档 |
| 命令行接口的名称、参数与调用约定 | CLI 文档 |
| 无固定结构的辅助性说明 | 模板体系外文档 |

## 3. 目录结构

### 3.1 docs 目录结构

`docs/` 下除中文资料 `docs/zh/` 外，还包含英文资料 `docs/en/`、站点首页 `docs/index.md` 与静态资源目录 `docs/assets/`、`docs/stylesheets/`。本规范以 `docs/zh/` 为强制执行范围（见[第1.2节](#12-适用范围)），中文资料目录按[第2.1节](#21-文档分层)的层级顺序排列如下：

```text
docs/zh/
├── install_guide/      # 安装指南
├── quick_start/        # 快速入门指南
├── user_guide/         # 用户指南：介绍业务流程和工具功能
├── best_practices/     # 典型案例
├── knowledge_base/     # 业务知识库：介绍 PTQ、W8A8 等术语概念，管理量化算法等知识
├── api_reference/      # 接口参考：方便用户查阅接口和配置信息
├── support/            # 问题支持
├── release_notes/      # 版本说明目录
├── legal/              # 许可证、声明、免责等所有法律相关文件
└── contributing/       # 贡献指南目录
    ├── contributing_guide.md    # 贡献指南
    ├── design/                  # 设计文档
    └── development_guide/       # 技术文档
```

### 3.2 命名规范

- 目录名与文件名使用英文小写，单词之间使用下划线连接，不得包含中文、空格及特殊字符。
- 目录的入口说明文件统一命名为 `README.md`。
- 若目录名或文件名须与代码实体（如 Python 类名）保持一致，可不受第一条约束。

## 4. 编写与校验

### 4.1 编写要求

文档编写要求分为通用要求与分类要求两类，前者不随文档类型变化，后者按文档类型而异：

- **通用要求**：适用于全部文档（含模板体系外文档），内容为与文档类型无关的编写约定，如标题结构、标点、术语、链接、图表与公式，统一见《[公共校验清单](00_common_checklist.md)》中的通用条目。各类文档的通用要求完全一致，故不设模板，直接以清单条目承载。
- **分类要求**：适用于模板体系内的5类文档，内容为章节结构及必填、选填章节，见对应模板；其专属判定条件见对应类型校验清单，模板与校验清单的对照关系见[第2.2节](#22-文档类型)。

### 4.2 校验要求

文档校验以《[公共校验清单](00_common_checklist.md)》中的通用条目与对应类型校验清单中的专属条目为依据。编写前应先阅读对应模板与《[公共校验清单](00_common_checklist.md)》，提交前按上述两类条目逐项校验。

- **严重级别**：`ERROR` 为必须满足的条目，`WARN` 为建议满足的条目。条目级别按以下方式划分：判定标准客观且影响读者阅读的列为 `ERROR`；需主观权衡或存在较多合理例外的列为 `WARN`。同一要求中兼有两类判定时，拆分为两条分别定级。
- **结论规则**：任一 `ERROR` 条目不满足，校验结论为**不通过**；仅 `WARN` 条目不满足，校验结论为**需修订**；全部满足，校验结论为**通过**。
- **校验执行**：新增文档后执行全量校验，修改文档后执行增量校验（仅校验变更文件及其受影响文件）。校验可由人工或 AI 代理执行，按校验清单逐项核对。
- **豁免机制**：确有合理原因无法满足某条目时，应在文档顶部声明 `<!-- waiver: 编号 原因：xxx -->`，校验时跳过该条目并记录原因；豁免不得用于规避超过2项 `ERROR` 条目，`WARN` 条目不设豁免数量上限。

## 5. 文档导航

文档之间应通过链接建立导航关系，分为业务流程图与知识图谱两类。

### 5.1 业务流程图

业务流程图表达业务作业流程与工具使用流程之间的上下层关系。

- **链接要求**：业务作业流程文档应链接其所依赖的每个工具使用流程文档；依赖多个工具时应分别链接，逐级嵌套。
- **覆盖要求**：除业务作业流程文档外，其他流程文档均应被上层流程文档链接，不得存在未被链接的流程文档。
- **外部工具要求**：流程中使用本仓库之外的第三方工具时，应提供该工具的官方使用指南链接。外部链接指向仓库外的文档不受本规范模板与校验清单的约束。
- **节点要求**：图中每个节点应为一篇流程指南文档，遵循《[流程指南模板](./02_process_guide_template.md)》；业务作业流程本身也是独立的流程文档，不得以虚拟分组替代。
- **范围要求**：术语词条、接口文档与案例不得作为业务流程图的节点，应由流程文档以链接形式引用。

### 5.2 知识图谱

知识图谱表达术语概念之间的关联关系。

- **链接要求**：术语词条应链接与其相关的其他词条并标注关系类型，同时应链接与其相关的流程文档。
- **连通要求**：每个词条应至少被其他一个词条链接，全部词条构成弱连通图，不得存在孤立词条。

## 6. 文档生命周期

- **新增与上线**：先按[第2.3节](#23-文档类型选择)确定文档类型，再按[第2.1节](#21-文档分层)与[第3.1节](#31-docs-目录结构)确定所属层级与目录，套用对应模板编写内容，并按[第4.2节](#42-校验要求)完成校验。上线时须接入[第5节](#5-文档导航)规定的导航关系。
- **评审与发布**：文档须按[第4.2节](#42-校验要求)校验通过，并经资料评审人员确认后方可发布。
- **变更**：功能、配置或接口变化，收到读者反馈，或所依据的模板与校验清单更新时，均应同步更新文档，并按[第4.2节](#42-校验要求)重新校验。
- **合并、拆分与更名**：文档合并、拆分或更名时，应删除原文档文件，并全量更新[第5节](#5-文档导航)及其他文档中指向原文档的链接，改为指向合并后、拆分后或更名后的文档。
- **废弃与下线**：功能下线或文档被其他文档替代时，应在版本说明中声明，并处理全部指向该文档的链接（改为链接到替代文档或删除链接）。

## 7. 规范维护

- **维护责任**：本规范由 SIG 归口维护，负责受理修订建议、组织评审、推动模板与校验清单同步更新，并维护修订记录。
- **反馈渠道**：资料编写、评审与维护人员发现规范缺失、冲突或不适用时，应通过仓库 Issue 或 SIG 例会提交修订建议，并说明受影响的范围与理由。
- **评审**：规范变更须经 SIG 评审通过后方可合入，并在修订记录中说明变更原因与影响范围。
- **同步演进**：新增或调整模板时，须同步更新对应校验清单；新增文档类型时，按[第7.1节](#71-校验清单编写约定)分配类型代码。本规范的文档类型表与目录结构同步维护。
- **生效与过渡**：本规范自合入之日起，对新编写与新修订的文档生效；已发布文档在下一次实质性修订时按本规范校验。确需批量整改时，由 SIG 设定过渡期并在修订记录中说明。

### 7.1 校验清单编写约定

校验清单的条目编号与类型代码遵循以下约定，各类型清单引用《[公共校验清单](00_common_checklist.md)》条目时直接写出编号，例如“见 CE-05”。

**编号格式**：本规范定义的校验清单中，全部条目采用 `<类型代码><级别代码>-<两位序号>`，例如 `CE-05` 表示公共清单中第5条 `ERROR` 条目。同一清单内，`ERROR` 与 `WARN` 分别从 `01` 起连续编号，不跳号。

**类型代码登记表**：

| 清单 | 类型代码 | ERROR 编号 | WARN 编号 |
| :--- | :--- | :--- | :--- |
| 公共校验清单 | C | CE-nn | CW-nn |
| 术语词条校验清单 | T | TE-nn | TW-nn |
| 流程指南校验清单 | P | PE-nn | PW-nn |
| 案例参考校验清单 | G | GE-nn | GW-nn |
| 配置文档校验清单 | F | FE-nn | FW-nn |
| 命令行 API 文档校验清单 | A | AE-nn | AW-nn |

**类型代码唯一性**：类型代码在本规范定义的校验清单中唯一，不得重复使用。新增文档类型时，应先在本表分配类型代码，再编写对应校验清单，并按[第2.2节](#22-文档类型)同步登记模板与校验清单。

**可选章节的引用方式**：可选章节的有无由模板中的 `[OPTIONAL]` 标记定义，校验清单不重复列举。校验清单引用模板中的可选章节时，应以章节名定位，不得写成模板中的章节编号：发布时可选章节须按公共清单 `CE-10` 删除与重新编号，编号在同类文档间并不一致。针对可选章节的校验要求写成条件式条目，以“仅当‘章节名’章节存在时校验”起首，未编写时不校验。

**例外处理**：校验清单不得为特定文档类型或特定文档设置例外条款，避免清单随个案累积“不强制”“除外”等从句而失去约束力。若某文档类型整体不适用某条目，应在该清单的“使用说明”中界定校验范围；若个别文档确有合理原因无法满足，应按[第4.2节](#42-校验要求)的豁免机制在文档顶部声明。
